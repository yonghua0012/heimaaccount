# 黑马记账

一款面向个人用户、本地优先的人民币支出记账桌面应用，支持 Windows 和 macOS。

> 当前状态：产品设计已确认，技术路线已选定为 Tauri 2；尚未开始编写应用代码。

## 2. 产品定义

“黑马记账”是一款不要求注册、不依赖网络、数据保存在用户本机的个人记账工具。产品的核心目标是让用户以尽量少的操作快速记下一笔支出，并能按月份回顾钱花在了哪些地方。

### 2.1 目标用户

- 希望自行保存财务数据，不希望上传到云端的个人用户。
- 需要一个简单、快速、可长期使用的桌面记账工具的用户。
- 主要使用 Windows 或 Mac 电脑，不需要手机端或多设备共享的用户。

### 2.2 核心价值

- 快：打开应用后可在 10 秒内完成一笔支出记录。
- 清：两级分类与月度统计帮助用户理解支出结构。
- 稳：金额精确、数据本地保存，并提供完整的备份与恢复能力。
- 私：应用完全离线运行，不上传财务数据。

## 3. 首版范围

### 3.1 支出记录

- 每笔记录包含金额、消费日期、二级分类和可选备注。
- 金额单位为人民币，单笔金额范围为 `¥0.01` 至 `¥99,999,999.99`。
- 日期默认当天，可选择一个有效的本地日历日期。
- 备注最多 200 个字符。
- 保存后立即更新当月合计、分类统计和最近记录。
- 用户可以修改记录的金额、日期、分类和备注。
- 删除记录前必须展示该记录摘要并要求二次确认。

### 3.2 分类管理

- 分类固定为两级：一级大类、二级小类。
- 每条支出只能选择一个处于启用状态的二级分类。
- 一级分类由所选二级分类的父级关系自动确定。
- 用户可以新增、重命名和停用一级、二级分类。
- 首版不提供分类的物理删除，使用“停用”隐藏分类；已产生记录的二级分类不能改挂到其他一级分类。
- 已停用分类的历史记录仍可正常展示和统计；新记录不能继续使用该分类。
- 分类名称最多 20 个字符，同一父级下的二级分类不能重名。

### 3.3 查询与回顾

- 默认按月查看支出，按消费日期倒序排列；同一天的记录按创建时间倒序排列。
- 支持按月份、一级分类、二级分类和备注关键词筛选。
- 支持在筛选结果中修改或删除记录。
- 月度统计以消费日期为准，不以记录创建时间为准。
- 一级分类合计必须等于其下所有二级分类合计之和。

### 3.4 数据管理

- 支持导出全部记录的 CSV 文件。
- 支持手动备份。
- 每天首次修改数据时自动备份，每天最多创建一份自动备份。
- 默认保留最近 30 份自动备份。
- 支持从备份恢复，并在恢复前校验备份完整性和结构版本。

### 3.5 首版不包含

- 收入、预算、账户余额和资产管理。
- 信用卡、转账、借贷和多币种。
- 云同步、账号系统、多人共享和手机端。
- 图片附件、语音输入和自动识别账单。
- 应用密码、数据库加密和生物识别。
- 深色主题。
- 自动更新。

以上内容不属于首版验收范围。新增这些能力时，应重新确认产品设计与数据安全方案。

## 4. 页面与交互

应用采用单窗口布局，左侧为固定导航，右侧展示当前页面。默认窗口约为 `1100 × 720`，最小可用窗口应保证表单、表格和统计数据完整可读。

### 4.1 总览

- 顶部显示当前月份和本月总支出。
- 主要区域提供“记一笔”入口、最近 10 笔记录和一级分类支出排行。
- 用户可以切换月份查看历史数据。

### 4.2 记一笔

- 以右侧抽屉形式打开，不离开当前页面。
- 输入顺序为：金额、一级分类、二级分类、日期、备注。
- 打开后金额输入框自动获得焦点。
- 一级分类选择后展示对应的二级分类。
- 最近使用和常用分类优先展示，并支持搜索。
- `Ctrl + Enter` 保存；macOS 使用 `Command + Enter`。
- `Esc` 取消录入。
- 保存时进行完整校验；成功后显示短暂提示，并刷新相关数据。

### 4.3 支出明细

- 以表格形式展示日期、一级分类、二级分类、备注和金额。
- 提供月份、分类和关键词筛选。
- 点击记录打开编辑界面。
- 删除前展示日期、分类、金额和备注摘要。
- 筛选无结果时显示空状态并允许清除筛选条件。

### 4.4 分类统计

- 展示当月总支出、一级分类金额和占比。
- 点击一级分类后展开对应的二级分类明细。
- 首版使用列表和横向占比条，保证数值与分类名称可同时阅读。
- 图表颜色不能作为区分分类的唯一方式。

### 4.5 设置

- 分类管理：新增、重命名、停用和调整未使用分类的层级归属。
- 数据管理：导出 CSV、立即备份、从备份恢复和打开数据目录。
- 关于：版本号、隐私说明和本地数据保存说明。

### 4.6 核心操作流程

打开应用 → 点击“记一笔” → 输入金额 → 选择一级分类 → 选择二级分类 → 按需修改日期或填写备注 → 保存 → 总览与当月合计自动更新。

## 6. 视觉与体验原则

“黑马记账”采用沉稳、利落的桌面工具风格。品牌主色为墨黑与暖金，主体背景使用暖白，传达速度、清晰和可信赖感。

- 金额使用等宽数字显示，统一格式为 `¥1,234.56`。
- 支出变化使用克制的琥珀色或红色，并同时配合符号和文字。
- 分类使用简洁的线性图标与稳定色块。
- 动效只用于抽屉打开、保存成功和统计切换。
- 支持完整键盘操作和清晰的焦点状态。
- 普通文字与背景的对比度至少为 4.5:1。
- 首版仅提供浅色主题。

## 7. 技术选型

### 7.1 候选方案

| 方案 | 组成 | 优势 | 劣势 | 结论 |
| --- | --- | --- | --- | --- |
| A. Tauri 2 | React + TypeScript + SQLite + Rust 外壳 | 安装包较小、内存占用较低；本地数据管理清晰；界面层可灵活扩展 | Rust 部分调试要求更高；不同系统 WebView 可能有细微差异 | 已选用 |
| B. Electron | React + TypeScript + SQLite + Chromium | 技术成熟、跨平台一致性高、资料与插件丰富 | 安装包通常较大，内存占用更高 | 未选用 |
| C. Flutter Desktop | Flutter + Dart + SQLite | 界面精致统一，未来扩展手机端方便，编译后性能较好 | 桌面生态相对较小，部分系统集成依赖插件 | 未选用 |

### 7.2 已确认技术路线

首版采用：

- 桌面外壳：Tauri 2
- 界面：React + TypeScript
- 构建：Vite
- 本地持久化：SQLite
- 系统能力：Tauri 的本地文件、对话框和平台适配能力

选择 Tauri 2 的原因是记账应用数据量和计算量有限，更适合做成轻量、启动快、完全本地的桌面工具。React 界面层便于后续实现统计视图、分类选择器和响应式布局。

### 7.3 构建与发布

- Windows 安装包在 Windows 环境中构建。
- macOS 安装包在 Mac 或 macOS 构建服务中构建。
- 首版发布 Intel 与 Apple Silicon 均支持的 macOS 安装包。
- Windows 首版优先发布 64 位安装包。
- 正式对外分发时需要配置 Windows 代码签名以及 Apple 签名和公证。
- 开发阶段生成的未签名安装包只用于内部测试。

## 8. 系统结构

应用采用“界面层、业务层、持久化层、平台适配层”的分层结构。

| 层级 | 职责 | 依赖 |
| --- | --- | --- |
| 界面层 | 展示页面、收集输入、维护筛选状态 | 业务层 |
| 业务层 | 校验金额和分类，管理记录、统计、备份和导出规则 | 持久化层、平台适配层 |
| 持久化层 | 通过 SQLite 执行事务、约束和查询 | 本地数据库 |
| 平台适配层 | 文件选择、目录打开、应用数据路径、安装包环境能力 | 操作系统与 Tauri |

### 8.1 业务模块

- 记录服务：新增、修改、删除和查询支出记录。
- 分类服务：管理一二级分类、启用状态和层级规则。
- 统计服务：计算月度总额、一级分类和二级分类汇总。
- 备份服务：创建、清理、校验和恢复备份。
- 导出服务：将记录转换为 UTF-8 CSV。
- 设置服务：保存上次使用分类、窗口偏好等本地设置。

各模块通过明确的数据接口协作。界面层不能直接修改数据库文件，也不能自行计算金额或分类统计。

## 9. 本地数据设计

### 9.1 数据表

| 数据表 | 主要字段 | 用途 |
| --- | --- | --- |
| `expense` | 编号、金额分值、消费日期、二级分类编号、备注、创建时间、修改时间 | 保存支出记录 |
| `category` | 编号、父级编号、名称、排序、启用状态、是否内置、创建时间 | 保存一二级分类 |
| `settings` | 键、值、修改时间 | 保存本地偏好 |
| `schema_version` | 版本号、升级时间 | 管理数据库结构版本 |

### 9.2 金额与日期

- 金额以“分”为单位存为整数。例如 `¥18.50` 保存为 `1850`。
- 输入框最多接受两位小数，保存前统一转换为整数分。
- 消费日期保存为 `YYYY-MM-DD`，按月统计不受时区影响。
- 备注保存为可选文本，首尾空白在保存前清理。

### 9.3 分类约束

- 一级分类的父级为空；二级分类必须有一个有效的一级父级。
- 支出只能引用二级分类，不能直接引用一级分类。
- 没有子分类的一级分类不能停用。
- 首版不提供分类的物理删除；已被历史记录引用的二级分类不能改变父级。
- 分类停用后仍可用于展示和统计历史记录。

### 9.4 数据目录

应用使用操作系统标准应用数据目录，逻辑结构如下：

```text
HeimaLedger/
├── heima-ledger.db
├── backups/
├── logs/
└── exports/
```

- Windows 和 macOS 使用各自的标准应用数据根目录。
- 应用内部文件名与目录名统一使用英文，界面显示中文名称。
- 设置页面提供“打开数据目录”入口。
- 首版不将数据目录默认放在应用安装目录，以免升级或卸载时误删数据。

## 10. 备份、恢复与导出

### 10.1 自动备份

- 应用启动后首次成功修改数据时，检查当天是否已有自动备份。
- 同一天最多创建一份自动备份。
- 默认保留最近 30 份健康备份。
- 自动备份失败不得阻止用户继续记账，但必须明确提示并提供手动备份入口。

### 10.2 手动备份

- 用户可以选择保存位置。
- 备份文件包含数据库结构版本和数据完整性校验信息。
- 保存失败时保留原文件并提示失败原因。

### 10.3 恢复

1. 用户选择备份文件。
2. 应用检查文件格式、数据库完整性和结构版本。
3. 校验通过后，先自动备份当前数据库。
4. 在临时位置写入恢复数据并再次校验。
5. 使用临时数据替换当前数据库，然后重新加载界面。

如果任何步骤失败，当前数据库保持不变，并保留损坏或不兼容文件的副本供排查。

### 10.4 CSV 导出

- 导出全部支出记录。
- 字段包含日期、一级分类、二级分类、金额（元）、备注和记录编号。
- 文件使用 UTF-8 编码并带 BOM，确保常见中文表格软件正确识别。
- CSV 仅用于查看和数据交换，不作为应用恢复源。

## 11. 隐私与安全

- 应用首版不启动业务网络请求，不上传、不分析、不共享财务数据。
- 本地数据权限依赖电脑登录账户和磁盘保护。
- 首版不提供应用密码，也不宣称数据库已经加密。
- 日志不得记录完整备注、完整金额组合或其他不必要的财务明细。
- 如果后续加入应用锁、数据库加密或云同步，必须单独完成安全设计和迁移方案。

## 12. 错误处理

应用必须使用用户能理解的提示说明问题和下一步操作。

| 场景 | 处理方式 |
| --- | --- |
| 金额为空、为零、为负或格式错误 | 阻止保存，保留已填写内容，聚焦金额输入框并说明格式 |
| 未选择二级分类 | 阻止保存，引导先选择一级分类再选择二级分类 |
| 分类已停用 | 阻止在新记录中使用，历史记录继续正常显示 |
| 数据库写入失败 | 回滚当前事务并提示重试；不得显示“保存成功” |
| 数据库损坏 | 保留损坏副本，提示从最近健康备份恢复 |
| 备份版本不兼容 | 拒绝恢复，不修改当前数据库 |
| 备份恢复中途失败 | 使用临时文件机制保护当前数据库，并展示失败原因 |
| CSV 导出失败 | 不生成半成品文件，提示检查目标目录和写入权限 |

删除记录、停用分类和恢复备份都需要明确的确认提示。恢复备份属于高风险操作，应显示将被替换的数据时间范围。

## 13. 质量与测试

### 13.1 自动测试

- 金额字符串与整数分之间的双向转换。
- 整数、两位小数、非法字符、极小值和极大值的边界校验。
- 月份第一天、最后一天及跨月数据统计。
- 一级分类统计等于其二级分类明细之和。
- 记录新增、编辑、删除后，总览和统计结果正确更新。
- 分类停用、重命名和引用约束。
- 备份创建、数量清理、完整性校验和恢复失败保护。
- CSV 编码、字段顺序、中文和金额格式。

### 13.2 集成与实机测试

- 关闭并重新打开应用后，记录和分类保持完整。
- Windows 与 macOS 均能完成首次启动、录入、筛选、统计、导出和恢复。
- 中文输入、文件名、安装路径和系统缩放比例下的显示正确。
- 使用至少 10,000 条记录验证列表、筛选和月度统计的可用性。
- 检查未签名开发包与正式签名包的启动和系统安全提示。
- 验证数据库升级成功，以及升级失败时不破坏原数据。

## 14. 交付顺序

### 阶段一：基础账本

- 建立桌面应用基础结构和本地数据库。
- 写入预置两级分类。
- 完成快速记账、记录编辑与删除。

### 阶段二：回顾能力

- 完成按月查询、分类与关键词筛选。
- 完成月度总览和两级分类统计。

### 阶段三：可靠发布
